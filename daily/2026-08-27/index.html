    • Bot v6.2 fix: hard stop now uses held_prices directly (same fix as TP + stale blocks)
    • Bot v6.0 scalp discipline: auto-TP at +30%/+100%/+300%, auto-stale exit at >60 min, prompt rewrite with SCALPING DISCIPLINE block
    • Bot v6.1 stale tightening: stale exit at >30 min and pnl < +20% (was 60 min + 30%). Added ⚠ STALE flag in prompt for positions held >15 min with pnl < +10%

    The Money Problem¶

    Status: 0.611 SOL of original 2.0 SOL. Lost 1.39 SOL (-69.5%)

    Where it went: | Outcome | Trades | Realized SOL | |---|---|---| | Explosive +500%++ | 19 | +3.11 | | Big +100-500% | 101 | +2.63 | | Good +30-100% | 76 | +1.29 | | Small +0-30% | 41 | +0.19 | | Small -30-0% | 126 | -1.43 | | Medium -60 to -30% | 104 | -4.32 ← bleeding here | | Big -90 to -60% | 40 | -2.28 ← and here | | Rug -99% | 5 | -0.34 | | NET | 512 | -1.14 |

    Why so bad: 1. Hard stop bug — biggest issue, just fixed in v6.2. ~277 losers × avg -45% × avg $5 actual loss = -1.2 SOL just from this. 2. Win rate 46% — under 50%, so any symmetric strategy loses. Need >55% to break even with the current win/loss size asymmetry. 3. Loss size > win size — losers ride to -50% (or worse pre-fix), winners sold at +30-50%. Need either tighter losers OR bigger winners. 4. Position size 0.1 SOL × 5 concurrent positions = 25% deployed. A -100% loss across all 5 = -25% portfolio in one bad batch.

    Quick wins to try: - Reduce position to 0.05 SOL (5 positions × 0.05 = 25% deployed, max loss per trade = $5) - Tighter stop at -30% (cut losers 2x faster, accept lower precision for capital preservation) - Let winners run to +200% before partial sell (currently sold at +30% which is too early)
